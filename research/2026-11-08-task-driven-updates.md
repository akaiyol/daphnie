# Task-driven automatic update decisions

Owner direction: give Daphnie responsibility and resources to advance her own scoped skill updates under a policy approved once. Resource choice: existing task budgets only. No recurring spending, new model allowance or background schedule is granted.

## Implementation

[Self-update guidance](../SELF_UPDATE.md) assigns candidate construction, resource checks, review requests and release follow-through to Daphnie. Protected core, flavour contracts, permissions, evaluator rules and acceptance data remain outside routine learning. Task-specific repairs stay in their owning project.

`advance-update` selects the next action using the active deployment and trusted evidence. It prepares eligible snapshots automatically, starts trials, promotes completed passing trials, rolls back signed failures, recognizes completed releases, or records a resumable deferral. It calls the existing signed release gates under their release lock; it neither issues signatures nor launches model attempts. Invalid signatures remain errors rather than deferrals presented as successful progress.

Private evidence blobs and `update_decision` events preserve exact submitted evidence and decision reasons. A restart can reevaluate the same bundle against the actual selected deployment; consumed grants do not cause duplicate publication. The supplied bundle is a host input, not generated by this command.

## Validation and limits

All 90 unit/integration tests passed. Nine focused update tests cover phase selection, automatic preparation, already-current recognition, missing grants, insufficient or unknown observations, failure rollback, forged/malformed evidence and the CLI. The package structure checker passed. These tests use synthetic judgments and disposable signers; they do not demonstrate useful learning, evaluator calibration or actual task-budget integration.

The pinned finite lifecycle model retains its existing transitions: this command chooses among the same signed gates and does not add a new activation authority. Source/module correspondence includes the decision driver. The checker and real-code replays must be run after changes to the covered command.

No production policy, signer, protected acceptance runner or trial observer is configured by this change. Operating guidance can direct an agent during a task but cannot enforce that every host invocation follows it. Existing installed skills require the updated canonical resources and a fresh context; the source workspace alone does not prove installation. Background operation and universal chat access remain absent.
